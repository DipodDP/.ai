# Конфигурация AI-инструментов

[English](README.md)

Версионируемая глобальная конфигурация AI-агентов для разработки — Claude Code и Gemini CLI. Файлы в этом репозитории — единственный источник истины; они применяются к системе через символические ссылки в `~/.claude` и `~/.gemini`, поэтому каждая правка здесь действует сразу и остаётся под контролем версий.

## Структура репозитория

| Путь | Назначение |
|------|-----------|
| `CLAUDE.md` | Глобальные стандарты работы агента для Claude Code (ссылка `~/.claude/CLAUDE.md`) |
| `GEMINI.md` | Те же стандарты для Gemini CLI плюс секция памяти Gemini (ссылка `~/.gemini/GEMINI.md`) |
| `claude_conf/settings.json` | Пользовательские настройки Claude Code: права, sandbox, плагины, skill overrides (ссылка `~/.claude/settings.json`) |
| `gemini_conf/settings.json` | Пользовательские настройки Gemini CLI (ссылка `~/.gemini/settings.json`) |
| `create_links.sh` | Создаёт все ссылки выше и линкует навыки из `~/.agents/skills` в `~/.claude/skills` |

Основные секции `CLAUDE.md` и `GEMINI.md` намеренно идентичны; отличается только секция «Gemini Added Memories» в конце `GEMINI.md`.

Навыки (skills) агентов живут в **отдельном репозитории** `~/.agents` (его каталог `skills/` линкуется скриптом в `~/.claude/skills`).

## Установка на новой машине

```sh
git clone <this-repo> ~/.ai
git clone <agents-repo> ~/.agents   # библиотека навыков; необязательно, но рекомендуется
cd ~/.ai && ./create_links.sh
```

Скрипт идемпотентен — его можно безопасно запускать повторно (например, после добавления нового навыка в `~/.agents/skills`). Если `~/.agents` отсутствует, скрипт выведет предупреждение и пропустит шаг с навыками.

## Правила использования

### 1. Держите файлы политик синхронными

`CLAUDE.md` и `GEMINI.md` редактируются **только вместе**. Добавляя правило, вносите одинаковый текст в одну и ту же секцию обоих файлов:

```sh
# после правки обоих файлов проверьте, что основные секции совпадают:
diff -B <(sed '/## Gemini Added Memories/,$d' GEMINI.md) CLAUDE.md
```

Расходиться может только секция «Gemini Added Memories».

### 2. Коммитьте сразу — этот репозиторий и есть бэкап

Незакоммиченные изменения — это незащищённая конфигурация. После любой правки:

```sh
git -C ~/.ai add -A && git -C ~/.ai commit -m "Описание изменения"
```

Периодически проверяйте `git -C ~/.ai status --short`.

### 3. Правьте файлы репозитория, а не копии

Благодаря симлинкам `~/.claude/settings.json` и `~/.ai/claude_conf/settings.json` — один и тот же файл. Если какой-то инструмент заменит симлинк обычным файлом, изменения перестанут попадать в репозиторий — проверяйте:

```sh
ls -la ~/.claude/settings.json   # должно показывать -> /Users/<you>/.ai/claude_conf/settings.json
```

Сломанные ссылки чинятся повторным запуском `./create_links.sh`.

### 4. Подключайте плагины на уровне проекта, глобально — минимум

Каждый глобально включённый плагин загружает свои инструменты и навыки в **каждую** сессию в каждом репозитории. В `claude_conf/settings.json` держите только универсально полезные плагины; тяжёлые и профильные включайте в проекте, которому они нужны:

```json
// <project>/.claude/settings.json — в этом проекте есть работа с дизайном
{ "enabledPlugins": { "figma@claude-plugins-official": true } }
```

```json
// <project>/.claude/settings.local.json — личное отключение в одном проекте
{ "enabledPlugins": { "playwright@claude-plugins-official": false } }
```

Приоритет: user < project < local — проект может включить то, что выключено в пользовательской конфигурации, а local переопределяет и то и другое.

### 5. Глобальные инструкции — короткие и исполнимые

Глобальные `CLAUDE.md`/`GEMINI.md` попадают в контекст каждой сессии. Оставляйте в них только правила, которые агент может выполнять где угодно (процесс согласования, TDD, гигиена коммитов). Доменные стандарты — в проект:

- Глобально: «не коммитить без согласования», «без упоминаний AI в коммитах»
- Проектный `CLAUDE.md`: REST-конвенции, формат JSON ошибок, политика миграций, «тесты через `make test`»

### 6. Ухаживайте за памятью Gemini

`save_memory` — только для фактов и предпочтений пользователя, общих для всех проектов. Проектные заметки — в `GEMINI.md` соответствующего проекта. Периодически перечитывайте секцию «Gemini Added Memories» и удаляйте дубли, устаревшие записи и противоречия — иначе она растёт только вширь.

### 7. Управляйте навыками через `~/.agents`

Добавляйте и правьте навыки в `~/.agents/skills/<name>/`, коммитьте там, затем запускайте `./create_links.sh`, чтобы прилинковать новые. Навыки, которые вы вызываете вручную, но которые модель не должна запускать сама, скрывайте, сохраняя команду `/name`:

```json
// claude_conf/settings.json
{ "skillOverrides": { "grill-me": "user-invocable-only" } }
```

### 8. Гигиена прав доступа

Deny-глобы должны покрывать любую вложенность, а не только корень проекта — `Read(**/.env)`, а не `Read(./.env)`. Если безопасный read-only инструмент постоянно запрашивает разрешение, добавьте его в `permissions.allow` здесь (под версионным контролем), а не через «always allow» в неверсионируемый локальный файл.
